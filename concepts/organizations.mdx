# Organizations

An **Organization** is the root container in Fanfare's multi-tenant architecture. Every piece of data - experiences, products, consumers, and audiences - belongs to exactly one organization.

## Organization Model

```typescript
interface Organization {
  // Identity
  id: string; // UUID
  slug: string; // URL-friendly identifier (e.g., "acme-corp")
  companyName: string; // Display name
  companyUrl?: string; // Company website

  // Localization
  languageCode: string; // Default language (e.g., "en")
  countryCode: string; // Default country (e.g., "US")
  timeZone: string; // Default timezone (e.g., "America/New_York")
  currencyCode: string; // Default currency (ISO 4217, e.g., "USD")

  // API Access
  publishableKey: string; // Client-side SDK key
  secretKey: string; // Server-side API key (never exposed)

  // SDK Configuration
  sdkPolicy: "latest" | "range"; // SDK version policy
  sdkVersionRange?: string; // Semver range if policy is "range"
  embeddingAllowedHosts?: string[]; // Allowed domains for SDK embedding

  // Messaging
  defaultMessagingChannel: "EMAIL" | "SMS";

  // Lifecycle
  state: "PENDING" | "ACTIVE" | "FAILED";
  createdAt: string;
  updatedAt: string;
}
```

## Organization States

Organizations go through a lifecycle during provisioning:

```
┌─────────┐     success      ┌────────┐
│ PENDING │─────────────────►│ ACTIVE │
└─────────┘                  └────────┘
     │
     │ failure
     ▼
┌────────┐
│ FAILED │
└────────┘
```

| State     | Description                                    |
| --------- | ---------------------------------------------- |
| `PENDING` | Organization created, provisioning in progress |
| `ACTIVE`  | Organization fully provisioned and operational |
| `FAILED`  | Provisioning failed, requires intervention     |

## Multi-Tenancy Pattern

Fanfare enforces data isolation at the database level using **composite primary keys**:

```sql
-- Every table includes organization_id in the primary key
CREATE TABLE experiences (
  organization_id UUID NOT NULL,
  id UUID NOT NULL,
  name TEXT NOT NULL,
  -- ... other columns
  PRIMARY KEY (organization_id, id)
);

-- Foreign keys also reference the composite key
CREATE TABLE sequences (
  organization_id UUID NOT NULL,
  id UUID NOT NULL,
  experience_id UUID NOT NULL,
  -- ... other columns
  PRIMARY KEY (organization_id, id),
  FOREIGN KEY (organization_id, experience_id)
    REFERENCES experiences(organization_id, id)
);
```

This pattern provides:

1. **Data Isolation**: No query can accidentally cross organization boundaries
2. **Query Efficiency**: Organization-scoped queries use the primary key
3. **Scalability**: Enables future sharding by organization

## API Keys

Each organization has two API keys:

### Publishable Key

- **Format**: `pk_live_...` or `pk_test_...`
- **Usage**: Client-side SDK initialization
- **Permissions**: Read-only access to public data
- **Safe to expose**: Can be included in browser bundles

```typescript
import { FanfareClient } from "@waitify-io/fanfare-sdk-core";

const client = new FanfareClient({
  publishableKey: "pk_live_abc123...",
});
```

### Secret Key

- **Format**: `sk_live_...` or `sk_test_...`
- **Usage**: Server-side API calls
- **Permissions**: Full read/write access
- **Never expose**: Keep server-side only

```typescript
// Server-side only
const response = await fetch("https://api.fanfare.io/v1/experiences", {
  headers: {
    Authorization: `Bearer sk_live_xyz789...`,
  },
});
```

## SDK Configuration

Organizations can control SDK behavior:

### SDK Policy

| Policy   | Behavior                          |
| -------- | --------------------------------- |
| `latest` | Always use the latest SDK version |
| `range`  | Pin to a specific semver range    |

```typescript
// Organization with range policy
{
  sdkPolicy: "range",
  sdkVersionRange: "^2.0.0"  // Allow 2.x.x only
}
```

### Embedding Security

Control which domains can embed the SDK:

```typescript
{
  embeddingAllowedHosts: [
    "www.example.com",
    "shop.example.com",
    "*.example.com", // Wildcard support
  ];
}
```

## Localization Defaults

Organization-level settings provide defaults for all experiences:

| Setting        | Purpose             | Example                   |
| -------------- | ------------------- | ------------------------- |
| `languageCode` | Default UI language | `"en"`, `"fr"`, `"ja"`    |
| `countryCode`  | Default country     | `"US"`, `"CA"`, `"GB"`    |
| `timeZone`     | Default timezone    | `"America/New_York"`      |
| `currencyCode` | Default currency    | `"USD"`, `"EUR"`, `"JPY"` |

These can be overridden at the experience level or per-consumer.

## Organization Slug

The slug is a URL-friendly identifier used for:

- Subdomain routing: `acme-corp.fanfare.io`
- API paths: `/organizations/acme-corp/...`
- Dashboard URLs: `app.fanfare.io/acme-corp`

### Slug Requirements

```typescript
// Validation rules
{
  minLength: 3,
  maxLength: 64,
  pattern: /^[a-z0-9][a-z0-9-]*[a-z0-9]$|^[a-z0-9]$/
}

// Valid examples
"acme"
"acme-corp"
"my-store-123"

// Invalid examples
"-acme"      // Cannot start with hyphen
"ACME"       // Must be lowercase
"ac"         // Too short
```

## API Operations

### Get Organization

```bash
GET /v1/organization
Authorization: Bearer sk_live_...

# Response
{
  "state": "ACTIVE",
  "publishableKey": "pk_live_...",
  "companyName": "Acme Corp",
  "slug": "acme-corp",
  "languageCode": "en",
  "countryCode": "US",
  "timeZone": "America/New_York",
  "currencyCode": "USD",
  // ... other fields
}
```

### Update Organization

```bash
PATCH /v1/organization
Authorization: Bearer sk_live_...
Content-Type: application/json

{
  "companyName": "Acme Corporation",
  "timeZone": "America/Los_Angeles",
  "embeddingAllowedHosts": ["www.acme.com", "shop.acme.com"]
}
```

### Check Slug Availability

```bash
GET /v1/organization/slug-availability?slug=new-slug
Authorization: Bearer sk_live_...

# Response
{
  "available": true,
  "suggestions": []
}

# Or if unavailable
{
  "available": false,
  "suggestions": ["new-slug-1", "new-slug-2", "new-slug-3"]
}
```

## Best Practices

### 1. Use Descriptive Slugs

Choose slugs that are:

- Recognizable to your team
- Stable (avoid changing after launch)
- Professional (will appear in URLs)

### 2. Configure Embedding Hosts

Always set `embeddingAllowedHosts` in production to prevent unauthorized SDK usage.

### 3. Rotate Keys Periodically

While keys don't expire automatically, rotate secret keys periodically:

1. Generate new key
2. Update server configurations
3. Revoke old key after verification

### 4. Set Appropriate Defaults

Configure timezone and currency to match your primary market - these affect how dates and prices display in consumer-facing widgets.
